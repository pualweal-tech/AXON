# AXON

AXON 是一个个人工作区，可对话、使用手工记忆、生成周计划，并在用户确认后把计划转为有日期的任务。客户端保留原有界面与主题。

## 本地运行

使用 Node.js 24 和 npm。在仓库运行 `npm ci`，再运行 `npm run dev`，浏览器打开 `http://localhost:5173`。生产构建用 `npm run build`；`npm start` 在同一个 Node 服务上提供构建后的页面和 API，默认监听本机 8787 端口。容器可显式设置 HOST、PORT。开发和生产服务应使用不同的存储目录。

- 默认本地数据库为仓库外的 `../.axon-data/axon.db`，可设置 AXON_DATA_DIR。本地开发首次运行自动创建加密密钥文件。备份与恢复需同时保留数据库及密钥；离线复制前先停止写入服务，或使用数据库一致性备份。
- 生产需要 AXON_ENCRYPTION_KEY。生成命令见 .env.example。会话使用随机不透明令牌，数据库只保存摘要，退出或恢复账号可使旧会话失效。切换加密密钥前应先用旧密钥重新加密已有供应商密钥。
- 在 Vercel 配置 Node.js 24、TURSO_DATABASE_URL、TURSO_AUTH_TOKEN 和 AXON_ENCRYPTION_KEY。单实例自托管可使用持久卷上的 SQLite。APP_ORIGIN 应填写浏览器看到的准确源（含协议与非默认端口），特别是经反向代理部署时。
- 正式环境开放注册需设置 RESEND_API_KEY 与已验证发信地址 AXON_MAIL_FROM。邮箱验证码 10 分钟内有效。设置 AXON_REGISTRATION=closed 可关闭注册。开发模式可本机注册；注册后单独保存恢复码。账号设置支持换密码、轮换恢复码、导出和删除。
- 在个人设置填写模型密钥，或由部署者显式配置服务级密钥。服务级密钥为没有个人密钥的账号承担费用。应用层每账号每分钟 12 次、每日窗口 100 次，全站每日窗口 1200 次；另应在供应商设置实际支出上限。

## 旧数据迁移

停用旧写入服务并备份受信任的服务端 data/axon.json。在空目标数据库运行 `npm run migrate:legacy -- <绝对路径/axon.json>`。存在旧供应商密钥时，临时设置原服务的 LEGACY_JWT_SECRET。导入事务会重新加密密钥、保留账号 ID 和业务记录；重复运行可识别完成标记。冲突或损坏会中止导入。导入后移除旧密钥配置并重新登录。旧的跨账号 Cookie 会被过期处理，曾经只存在于已销毁实例且没有可信备份的数据无法从服务端重建。

## 使用与恢复

- 工作区按账号和版本同步，离线修改留在本机待同步区。独立修改可自动合并。同一字段冲突时，先导出双方需保留的内容，再决定是否采用云端版本。共享设备使用完毕请完成同步并退出。
- 周计划读取未完成任务、近期计划和相关笔记。可以在工作区导入所选周的 .ics 日历；导入前可确认事件数量。转换任务保留日期、时间及来源 ID，重复转换可去重。模型可用 taskId 引用已有任务，经确认后调整该任务的日期和时间；与导入的日历占用时段冲突时会跳过并提示。周计划右上角可导出 .ics，用户导入系统日历后由日历应用负责定时提醒。在应用内的到期提示需要页面保持打开。
- 模型以流式方式生成内容。工作区可重开最近 24 小时内的已完成结果，并重试失败或超时的运行。运行记录归属当前账号；成功后清除用于重试的输入，日志只记录请求标识、类型和耗时。数据保留窗口随服务请求清理。
- 图片支持 OpenAI 的 PNG/JPEG/WebP 视觉输入，最多约 1.4 MB；语音依赖浏览器 SpeechRecognition 和麦克风权限。文档支持文本、Markdown、CSV、JSON 和 HTML。网页摘要在浏览器取得正文后生成，目标站需允许跨域读取。超出输入上限时可选取所需段落。
- 通知、恢复、模型供应商和数据库的实际外部连通性，需要在目标部署环境单独验证。

## 验证

`npm test` 运行隔离数据库和模拟供应商回归；`npm run build` 对客户端、API、服务端和测试做严格类型检查并打包。CI 同时检查生产依赖公告。部署后核验 /api/health、邮箱注册、跨实例登录、保存和真实模型流式回答。
